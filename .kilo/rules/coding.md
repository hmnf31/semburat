# Coding Rules

- Prefer readable, maintainable code over clever code.
- Keep functions/modules focused.
- Use strict typing where practical.
- Validate external input at boundaries.
- Handle errors explicitly.
- Do not silently swallow exceptions.
- Avoid magic constants; centralize configuration.
- Do not hardcode secrets.
- Add tests for important business logic.
- Avoid unrelated refactors during feature work.
- Keep generated code reviewable.
- Update documentation when behavior changes.
